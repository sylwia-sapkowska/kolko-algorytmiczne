Część 1

Złożoność

Dwa programy, ten sam wynik

Oba liczą sumę $1 + 2 + \dots + n$.

Program A

long long n, s = 0;
cin >> n;
for (long long i = 1; i <= n; i++)
    s += i;
cout << s;

Program B

long long n;
cin >> n;
cout << n * (n + 1) / 2;
Ile pracy wykona każdy z nich dla $n = 10^9$?
  • A: miliard obrotów pętli, za każdym razem dodawanie i porównanie
  • B: jedno mnożenie, jedno dodawanie i jedno dzielenie, niezależnie od $n$

  • interesuje nas, jak liczba kroków rośnie, gdy $n$ rośnie
Program A robi około $n$ kroków, program B stałą liczbę.

Jedna pętla: $n$ kroków

// największa liczba w tablicy
int mx = a[0];
for (int i = 1; i < n; i++)
    if (a[i] > mx)
        mx = a[i];
  • pętla obraca się $n - 1$ razy
  • w każdym obrocie: porównanie i czasem przypisanie
  • razem około $c \cdot n$ kroków, dla jakiejś stałej $c$

Dwa razy więcej liczb to dwa razy więcej pracy. Mówimy, że to złożoność liniowa.

Pętla w pętli: około $n^2$ kroków

// ile jest par i < j z a[i] + a[j] == 10?
int ile = 0;
for (int i = 0; i < n; i++)
    for (int j = i + 1; j < n; j++)
        if (a[i] + a[j] == 10)
            ile++;

Dla $i = 0$ wewnętrzna pętla robi $n-1$ obrotów, dla $i = 1$: $n-2$, …, dla $i = n-1$: zero.

$$(n-1) + (n-2) + \dots + 1 + 0 = \frac{n(n-1)}{2}$$

To około $\frac{1}{2} n^2$: złożoność kwadratowa. Dwa razy więcej liczb to cztery razy więcej pracy.

Pętla, która dzieli na pół: $\log_2 n$ kroków

int k = 0;
while (n > 1) {
    n /= 2;
    k++;
}

Dla $n = 1000$:

$$1000 \to 500 \to 250 \to 125 \to 62 \to 31 \to 15 \to 7 \to 3 \to 1$$

9 obrotów. Dla $n = 10^6$: 19 obrotów.

Liczba obrotów to około $\log_2 n$: ile razy trzeba podzielić $n$ przez 2, żeby dojść do 1. To złożoność logarytmiczna.

Gdy $n$ rośnie tysiąc razy, $\log_2 n$ rośnie tylko o około 10.

Notacja $O$: liczy się najszybciej rosnący składnik

  • pomijamy składniki, które rosną wolniej: zostaje $3n^2$
  • pomijamy stałą $3$: zależy od komputera i od tego, co nazwiemy krokiem
Zapisujemy $f(n) = O(n^2)$ i czytamy: „$f$ rośnie najwyżej tak szybko jak $n^2$”.

Definicja $O$ dla chętnych

$f(n) = O(g(n))$, jeśli istnieją stałe $c > 0$ i $n_0$ takie, że $$f(n) \le c \cdot g(n) \quad \text{dla wszystkich } n \ge n_0.$$

Przykład: $3n^2 + 5n + 2 = O(n^2)$. Dla $n \ge 1$ mamy $n \le n^2$ i $1 \le n^2$, więc

$$3n^2 + 5n + 2 \le 3n^2 + 5n^2 + 2n^2 = 10 n^2.$$

Wystarczy wziąć $c = 10$ i $n_0 = 1$.

$O$ to ograniczenie z góry. Prawdą jest też $n = O(n^2)$, ale zwykle podajemy najmniejsze ograniczenie, jakie umiemy uzasadnić.

Jak szybko rosną funkcje

Liczba kroków dla wybranego $n$ i czas przy około $10^8$ prostych operacjach na sekundę.

Skala jest logarytmiczna: każda kreska to 100 razy więcej kroków. Przerywana linia to $10^8$ kroków, czyli około sekundy. Zielony: mieści się, czerwony: nie.

Od jakiego $n$ algorytm $O(n^2)$ przestaje mieścić się w sekundzie?

Około $n = 10^4$: $n^2 = 10^8$.

Ograniczenia w zadaniu podpowiadają algorytm

Komputer robi około $10^8$ prostych operacji na sekundę. To szacunek rzędu wielkości, ale wystarcza do wyboru metody.

Liczymy najgorszy przypadek

// czy x jest w tablicy?
bool jest = false;
for (int i = 0; i < n; i++)
    if (a[i] == x) {
        jest = true;
        break;
    }
Ile obrotów zrobi pętla?
  • $x$ jest w a[0]: jeden obrót
  • $x$ nie ma w tablicy: $n$ obrotów

Nie wiemy, jakie dane dostaniemy, więc liczymy najgorszy przypadek: wyszukiwanie ma złożoność $O(n)$.

Jaka to złożoność?

for (int i = 0; i < n; i++)
    s += a[i];
for (int j = 0; j < n; j++)
    t += a[j];

$O(n)$: dwie pętle po kolei to $2n$ kroków

for (int i = 0; i < n; i++)
    for (int j = 0; j < 5; j++)
        s += a[i] * j;

$O(n)$: wewnętrzna pętla ma zawsze 5 obrotów

for (int i = 0; i < n; i++)
    for (int j = 0; j < i; j++)
        s += a[j];

$O(n^2)$: $0 + 1 + \dots + (n-1) = \frac{n(n-1)}{2}$

for (int i = 0; i < n; i++)
    for (int j = 1; j < n; j *= 2)
        s += a[i];

$O(n \log n)$: $n$ razy pętla, która podwaja $j$

Część 2

Sortowanie

ustawiamy liczby od najmniejszej do największej

Czy jakaś liczba się powtarza?

bool powtorka = false;
for (int i = 0; i < n; i++)
    for (int j = i + 1; j < n; j++)
        if (a[i] == a[j])
            powtorka = true;

Sprawdzamy każdą parę: $\frac{n(n-1)}{2}$ porównań, czyli $O(n^2)$.

Dla $n = 10^6$ to około $5 \cdot 10^{11}$ porównań: zdecydowanie za dużo.

A gdyby liczby były posortowane?

Równe liczby stałyby obok siebie. Wystarczy porównać każdą z następną: $n - 1$ porównań.

Po posortowaniu wiele zadań staje się prostszych. Pytanie: ile kosztuje samo sortowanie?

Sortowanie przez wybór

Znajdź najmniejszą liczbę i postaw ją na początku. Potem najmniejszą z pozostałych na drugim miejscu, i tak dalej.

for (int i = 0; i < n - 1; i++) {
    int m = i;  // pozycja minimum
    for (int j = i + 1; j < n; j++)
        if (a[j] < a[m])
            m = j;
    swap(a[i], a[m]);
}

żółty: porównywane teraz · fioletowy: zamiana · zielony: już na swoim miejscu

Ile porównań robi sortowanie przez wybór?

$$(n-1) + (n-2) + \dots + 1 = \frac{n(n-1)}{2}$$

Dla $n = 8$: $28$ porównań. Tyle samo pokazuje licznik w widżecie.

Zamian jest tylko $n - 1$, ale porównań zawsze około $\frac12 n^2$, nawet gdy tablica jest już posortowana.

Sortowanie przez wybór: $O(n^2)$ zawsze.

Sortowanie bąbelkowe

Idziemy od lewej do prawej i zamieniamy sąsiadów, którzy stoją w złej kolejności. Po pierwszym przejściu największa liczba jest na końcu.

for (int i = 0; i < n - 1; i++)
    for (int j = 0; j + 1 < n - i; j++)
        if (a[j] > a[j + 1])
            swap(a[j], a[j + 1]);

Porównań: $\frac{n(n-1)}{2}$, czyli $O(n^2)$.

Ulepszenie: jeśli w całym przejściu nie było żadnej zamiany, tablica jest posortowana i można skończyć.

Sortowanie przez wstawianie

Jak przy układaniu kart w ręce: początek tablicy jest już posortowany, a kolejną liczbę przesuwamy w lewo, aż trafi na swoje miejsce.

for (int i = 1; i < n; i++) {
    int j = i;
    while (j > 0 && a[j - 1] > a[j]) {
        swap(a[j - 1], a[j]);
        j--;
    }
}

zielony: posortowany początek tablicy

Wstawianie: najlepszy i najgorszy przypadek

daneporównaniazamiany

Dla $n = 8$: $7$ albo $28$ porównań. Sprawdź przyciskami „posortowana” i „odwrócona”.

Każda zamiana naprawia jedną parę liczb stojących w złej kolejności. Gdy takich par jest mało, sortowanie przez wstawianie jest szybkie.

Najgorszy przypadek: $O(n^2)$. Prawie posortowane dane: prawie $O(n)$.

Scalanie dwóch posortowanych ciągów

  • patrzymy tylko na pierwsze niewzięte elementy obu połówek
  • mniejszy z nich dopisujemy do wyniku
  • gdy jedna połowa się skończy, dopisujemy resztę drugiej

Każde porównanie dopisuje jeden element, więc porównań jest mniej niż $n$.

Scalenie dwóch posortowanych ciągów o łącznej długości $n$: $O(n)$.

Sortowanie przez scalanie

  1. podziel tablicę na dwie połowy
  2. posortuj każdą połowę tą samą metodą
  3. scal posortowane połowy

Na każdym poziomie scalamy łącznie $n$ elementów: $O(n)$. Poziomów jest $\log_2 n$, bo za każdym razem połowimy.

$O(n) \cdot \log_2 n = O(n \log n)$, w każdym przypadku.

Sortowanie przez scalanie w C++

// sortuje a[l], a[l+1], ..., a[r-1]
void sortuj(vector<int>& a, int l, int r) {
    if (r - l <= 1) return;  // 0 lub 1 element
    int m = (l + r) / 2;
    sortuj(a, l, m);
    sortuj(a, m, r);

    vector<int> b;  // wynik scalania
    int i = l, j = m;
    while (i < m && j < r) {
        if (a[i] <= a[j]) { b.push_back(a[i]); i++; }
        else              { b.push_back(a[j]); j++; }
    }
    while (i < m) { b.push_back(a[i]); i++; }
    while (j < r) { b.push_back(a[j]); j++; }

    for (int k = 0; k < r - l; k++)
        a[l + k] = b[k];
}
// wywołanie: sortuj(a, 0, n);

fioletowy i różowy: scalane połowy · dolny rząd: wektor b

Szybciej niż $n \log n$ się nie da

Dotyczy każdego algorytmu, który tylko porównuje elementy.

  • $n$ liczb można ustawić na $n!$ sposobów i algorytm musi odróżnić każdy z nich
  • po $h$ porównaniach możliwych jest najwyżej $2^h$ różnych przebiegów
  • potrzeba $2^h \ge n!$, czyli $h \ge \log_2 n!$

Dla $n = 3$: $3! = 6 > 2^2$, więc co najmniej 3 porównania. Dla $n = 8$: $8! = 40\,320$, więc co najmniej 16.

$\log_2 n! \ge \frac{n}{2} \log_2 \frac{n}{2}$, bo połowa czynników $n!$ jest $\ge \frac{n}{2}$. To jest rząd $n \log n$.

Sortowanie przez zliczanie: małe liczby w $O(n + k)$

Gdy wartości są liczbami całkowitymi od $0$ do $k$, nie trzeba porównywać.

vector<int> ile(k + 1, 0);
for (int i = 0; i < n; i++)
    ile[a[i]]++;

int p = 0;
for (int v = 0; v <= k; v++)
    for (int c = 0; c < ile[v]; c++) {
        a[p] = v;
        p++;
    }

Złożoność $O(n + k)$, pamięć $O(k)$.

Opłaca się, gdy $k$ jest małe, np. oceny 1–6 albo wiek w latach. Dla $k = 10^9$ tablica ile się nie zmieści.

W praktyce: sort

#include <algorithm>
...
vector<int> a = {5, 2, 8, 1};

sort(a.begin(), a.end());    // 1 2 5 8
sort(a.rbegin(), a.rend());  // 8 5 2 1
  • begin, end: od początku do końca, rosnąco
  • rbegin, rend: od końca do początku, więc wychodzi malejąco
  • złożoność $O(n \log n)$
vector<pair<int, int>> p =
    {{2, 5}, {1, 7}, {2, 3}};

sort(p.begin(), p.end());
// {1, 7} {2, 3} {2, 5}

Pary sortują się jak słowa w słowniku: najpierw po pierwszej liczbie, a przy remisie po drugiej.

W zadaniach sortujemy funkcją sort. Własne sortowanie piszemy, żeby zrozumieć, jak działa i ile kosztuje.

Wracamy do powtórzeń

sort(a.begin(), a.end());
bool powtorka = false;
for (int i = 0; i + 1 < n; i++)
    if (a[i] == a[i + 1])
        powtorka = true;
  • sortowanie: $O(n \log n)$
  • jedno przejście po sąsiadach: $O(n)$
  • razem $O(n \log n)$

Dla $n = 10^6$: około $2 \cdot 10^7$ kroków zamiast $5 \cdot 10^{11}$.
